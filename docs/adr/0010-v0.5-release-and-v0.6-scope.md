# ADR 0010 — v0.5.0 release shape; GPU runner and release polish move to v0.6

Status: accepted
Date: 2026-09-29

## Context

v0.5.0 (run `v0.5.0-20260929-1648`) is trained and staged but not published. Its 8-bit ONNX is
598,046,561 bytes. The run stays in private R2 at `openjevx-train/runs/v0.5.0-20260929-1648/`, and
the trainable checkpoint is `checkpoint.tar.gz` (777 MB). The gate finished the basics sets:

| Gate set | right & confident | confidently wrong | limit |
|---|---|---|---|
| Everyday basics (469) | 98.9% | 0.6% | pass |
| Condition basics (300) | 94.3% | 3.7% | **miss** (limit 2%) |

The owner accepted the condition-basics miss for release. Every note and card must state it.
When this was written, the rest of the gate (`conditions_eval`, `it_worker_eval`, `logs_gate`) and
the benchmark report (llmresults/11, branch `bench/v0.5-benchmarks`) had not finished.

The owner's home upload is slow. Publishing the full v0.4.0 asset set would mean about 4.7 GB of uploads.

## Decision

1. **OpenJevX is a CPU-first decision model that you run in a container.** We ship one 8-bit ONNX
   (ADR 0003). No more training for v0.5.0: we ship what we have.
2. **What v0.5.0 publishes:**
   - Hugging Face: `openjevx.w8.onnx` plus the fine-tune files (`model.safetensors`, `encoder/`,
     `tokenizer/`, `rl_agent_config.json`). No datasets. Before the upload, tag the current HF main
     `v0.4.0` so the old model stays reachable.
   - GitHub release: `openjevx.w8.onnx.zip` and the macOS, Linux and Windows executables.
     **No Docker tars**: users build the image with `docker compose up -d --build`.
   - Public R2 `openjevx`: `openjevx-finetune-v0.5.0.tar.gz`, a server-side copy of the checkpoint.
     Nothing is uploaded from home for it.
3. **The HF card says where the model stands**, using the benchmarks and the gate, including the miss.
   It has no old-vs-new version table. Version deltas may go in GitHub release notes.
4. **Users are told to run `jevx cache clear`** after upgrading, or to use a versioned model name,
   because jevx caches answers by model name.

## Deferred to v0.6

- **GPU runner:** an fp16 ONNX for the Go server's `gpu` mode, published on HF and in public R2.
  It must be exported and benchmarked on CUDA against the 8-bit file (ADR 0003), on a Vast box
  that writes to R2 (ADR 0009). One attempt on 2026-09-29 was cancelled before any output; it cost about $0.03.
- **Fix the condition-basics confidently-wrong rate** (3.7%) to within the 2% limit.
- Finish publishing v0.5.0 if it is not done first: the full gate report, merging report 11, and the
  site results page.

## Consequences

Branch `publish-v0.5.0` holds the version bumps (README, Taskfile, Dockerfile, `scripts/package.sh`,
`bin/openjevx.js`, `package.json`, site) and this ADR. The release packages, the HF staging folder
and the ONNX zip are in the worktree's `.local/` (not committed). Because Docker users build from
source and the Dockerfile downloads the model from the v0.5.0 release, **main must not get these
version bumps until the v0.5.0 release exists.**
