# Report 5 — Fine-tune plan (vast.ai → Hugging Face + GitHub release)

## Inputs (already in `data/`, Apache-2.0)
- `train_openjevx.jsonl` — 2.14M records in the model's own format (state, questions, gold).
- `eval_openjevx.jsonl` — 26.5k held-out records.
- `jev_train_all.jsonl` — 5.4M flat premise/hypothesis/label rows. These map to yes/no questions
  (premise = state, hypothesis = statement). Mixed in as a sampled slice, not all of it.

## Steps
1. **Keep data out of git.** Add `data/*.jsonl`, `data/raw/` to `.gitignore`. Commit only the scripts.
2. **Build the training shard locally** with `scripts/kaggle/package_kaggle.py`: priority sources
   (typed-decisions, our cases) in full, the rest sampled to a budget. The shard is gzipped and
   then uploaded to the box. Nothing gets improvised on the paid machine.
3. **Smoke first**: a 15-minute run on the box measures real throughput, then the full run is sized
   from that (epochs × items fit the time budget).
4. **Train on vast.ai** with the existing recipe (ADR 0002: fp16 autocast, lr 2.5e-5 / 1e-4,
   cosine), then per-type temperature calibration, then fp32 ONNX export on CUDA.
   A detached watcher pulls the artifacts and destroys the box on success, failure or timeout.
   The box is labelled `openjevx-...-DESTROY-AFTER`.
5. **Gate locally on the exact shipped file** (4-bit weight-only via `scripts/quantize_w4.py`, run
   through the Go server):
   - public typed-decisions test ≥ 80% (today 76.1%)
   - held-out `eval_openjevx` measurably better than v0.3.0
   - everyday rule set + opencode set: no regression, ideally a large gain
   - spike: answers flip when the deciding fact flips; stable across batching
   If the gate fails, nothing is published.
6. **Publish**
   - **Hugging Face** `muthuishere/openjevx`: fine-tuned safetensors checkpoint + tokenizer +
     config, `openjevx.onnx` (fp32), `openjevx.w4.onnx`, model card with the gate numbers.
     No training data.
   - **GitHub release v0.4.0**: server packages with the new model embedded, Docker tars,
     `openjevx.w4.onnx`, fp32 zip, and the source code (training scripts + data generators, no
     data files) + a README: generate data, train on Kaggle / vast / any CUDA box, export,
     quantize, serve.
   - README + ADR updated.

## Cost / time
Unknown until the smoke measures throughput. The full 2.14M records × 4 epochs would take days on
one GPU, so the run is capped by a time budget and the data is sampled to fit.

## Decisions since (owner)
- **Speed:** target ~3 h on one RTX 4090 (~$1.50), cap $15. Sample ~300-500k decisions, 1 pass,
  max input 512 tokens, bf16, larger batches; a 15-minute smoke run measures real speed first.
- **Data coverage:** add a large rule-labelled set for every software role: operations/SRE,
  developers, testers/QA, tech leads, managers, plus basics everyone needs (an outage beats tea).
  Generated by a Sonnet subagent (`scripts/data/gen_it_worker.py`), then blind-audited by Haiku.
- **What gets shared:** Hugging Face and the GitHub release get ONLY the fine-tuned model and ONNX.
  The GitHub release also carries the source (training scripts + data generators) so anyone can
  rebuild data and fine-tune. No training data is published anywhere.
- **Data to the GPU box:** private Hetzner S3 bucket + 24 h signed link (`scripts/vast/presign.py`
  under `sec`). No credentials on the box.
- `data/*.jsonl` is gitignored.
