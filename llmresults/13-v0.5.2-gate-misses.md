# Report 13 — why v0.5.0 is confidently wrong on the basics gates, and the v0.5.2 fix

Model: `openjevx-0.5.0` (sha256 `109b2b1d…`). Gates: `gate/basics_gate.jsonl` (463 scored) and
`gate/conditions_basics_gate.jsonl` (300), unchanged since v0.5.0 (same sha256). Scorer: `finetuning/gate/gate_eval.py`
(jevx defaults: yes >= 0.8, no <= 0.2, choice/score >= 0.6).

| Gate | right & confident | confidently wrong | limit |
|---|---|---|---|
| Everyday basics (463) | 96.3% | 3.0% (14) | <= 2% |
| Rule-checking basics (300) | 94.3% | 3.7% (11) | <= 2% |

## Method

One run of the model with every temperature set to 20 recovers each answer's raw logits (`z = 20 * ln p`).
After that, any temperature or threshold can be replayed offline. The replay matches the real gate exactly
(3.0% / 3.7%).

## Recalibration cannot fix it

The model is saturated: right answers and confidently wrong answers sit at the same raw margin, which is the
head's ceiling of about 4.9 logits (right: median 4.89, 5th percentile 4.57; wrong: median 4.56, max 4.90).
A temperature cannot separate them:

| noul temperature | everyday: right&conf / conf-wrong | rule-checking: right&conf / conf-wrong |
|---|---|---|
| 1.25 (v0.5.0) | 96.3% / 3.0% | 94.3% / 3.7% |
| 2.0 | 95.7% / 2.2% | 94.0% / 3.7% |
| 2.5 | 95.0% / 1.9% | 93.7% / 3.7% |
| 3.0 | 93.7% / 1.7% | 93.0% / 3.7% |
| 3.5 | 71.1% / 0.0% | 67.0% / 1.7% |

The rule-checking gate does not move until right & confident collapses. Choosing temperatures on the gate would
also fit the test. **A retrain is needed.**

## The misses: three causes, none of them label noise

Every gold was re-derived by hand from the rule. All 25 confident misses are correct labels.

1. **The model remembers each rule's number instead of reading it (6 of 14 everyday).** The basics train set
   states one threshold per rule. The gate states a different one, and the model answers with the train one:
   - `min_balance`: gate Rs 5000, train Rs 1000. It says 1126, 4998 and 4999 are *not* under the minimum, which is
     exactly right for Rs 1000.
   - `credit_score`: gate 750, train 700. It says 748 and 749 qualify.
   - `child_ticket` (gate under 3, train under 5): age 15 at p=0.76. Unsure, not wrong.
2. **The gate's formats never appear in train (8 of 14 everyday).**
   - `freezing` at 0.1, 0.2 and 0.5 C was called "at or below 0 C". Train only has whole-number readings for this rule.
   - Meetings that start on the half hour: 3 confident misses. Train meetings are all on the hour.
   - `passport_valid` asks "unexpired?" with a 2028 date: 2 misses. Train dates stop in early 2028, and train has
     no negated date questions.
3. **No training data for a bare date compared with today (10 of 11 rule-checking).** The question is "Given today is
   X, has the deadline Y already passed?", with no rule text. The model says "passed" in 4/4 same-day cases and 6/26
   future cases. The 26 past cases are all right. The 11th miss is `age_adult` at age 99, outside the usual range.

The unsure answers (null check, status equals "rejected" vs "cancelled", list membership) cost right & confident,
not confidently wrong.

## jevx 13 fundamentals: the scored 11/13 is really 12/13

`jevx13.sh` passed `SEV="How severe is this incident?|low;medium;high"`. jevx keeps the inner quotes, so the third
label was `high"`. The model picked it correctly, but the script compared it to `high`. Fixed in
`finetuning/gate/jevx13.sh`. The one real miss is `ERROR db refused (500) -> act`, which is unsure at 0.76.

## Fix (v0.5.2): rule-reading drills, no change to the gates or test sets

New generator `finetuning/dataprep/gen_rule_reading.py` -> `train/rule_reading_train.jsonl`. Every gold comes from
evaluating the rule:

- **thresholds**: every everyday numeric rule with 24 thresholds instead of one, never the gate's threshold.
- **decimals**: decimal readings against whole-number thresholds. Freezing and boiling are left out on purpose, so
  the gate checks that the skill transfers to them.
- **dates**: 2020-2035, heavy on same-day and +-1 day, plus negated questions. Passport and subscription are left out,
  so the gate's negated wording still tests transfer.
- **bare dates**: a date against today, with no rule text, never on one of the gate's "today" dates.
- **meetings**: quarter-hour starts (not :30), 30-120 minutes, back-to-back cases.
- **fields**: null, status equals, list contains, and a number against a threshold stated in the question.

Every row whose state a gate or test file asks about (leak_check's state test, any question type) is dropped. The
v0.5.0 training files are reused unchanged. `conditions_train.jsonl` does not regenerate byte-identical
(28.5k of 50k rows match), so `gen_conditions.py` is nondeterministic. That is unrelated to this fix and is not
changed here.

## Outcome

Two GPU runs on Vast.ai (RTX 4090), total **$2.77** (credit $90.31 -> $87.54). Every box was destroyed;
`vastai show instances` is empty.

| Run | What | Cost |
|---|---|---|
| run 1 smoke + full (`v0.5.2-20261002-1244`, commit 2189da0) | drills x2, basics x5; 778k decisions | ~$1.30 |
| run 2 smoke | commit c948170 | ~$0.05 |
| run 2 full, first box | the host stopped it before `run_job.sh` started; destroyed by hand. `vast.py` now destroys and fails a box that exits like that (4ac777c); before, it would have waited out the 7.5 h deadline | ~$0.15 |
| run 2 full (`v0.5.2-20261002-1706`, commit 4ac777c) | drills x3 (+ wordings, zero decimals, opening hours), basics x2; 791k decisions, 2.5 h | ~$1.25 |

**Run 1** fixed rule-checking (3.7% -> 0.0%), but everyday basics only reached 2.6% (12/463). The probes showed
four causes:
- `credit_score` at 750: the yes/no boundary stayed between 600 and 671 whatever the wording, so the x5
  fixed-threshold basics set still outweighed the drills;
- `child_ticket` "under 3": wrong only with the gate's "young enough" wording;
- 0.1 C still called freezing;
- quiet hours 21-24: time windows were never drilled.

Run 2 adds "young/old/high/low enough" wordings, decimals around zero on other rules (not freezing), and
opening-hours windows (never the gate's). It moves basics x5 -> x2 and drills x2 -> x3.
